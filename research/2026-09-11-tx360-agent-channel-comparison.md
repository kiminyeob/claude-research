# TX360 AI 에이전트 — 채널 후보 비교

> 작성일 2026-09-11 · 목적: **최종 후보를 좁히기 위한 논의 자료**
> 이 문서는 PoC 결과 보고서가 아니다. 공개 문서를 근거로 후보를 같은 기준에 놓고 비교한 것이다.

## 0. 한 장 요약

**하려는 일** — 사내망 전용 시스템인 TX360의 정보·콘텐츠를 임직원이 AI 에이전트로 **조회**하게 한다. 이후 단계로 **등록**까지 확장한다.

**이번 조사의 결론 한 문장**

> 병목은 "어느 채널에서 쓰게 할까"가 아니라 **"사내망을 어떻게 넘을까"**다.

이유는 단순하다.

- Claude에 등록하는 **리모트 커넥터의 호출은 사용자 PC가 아니라 Anthropic 클라우드에서 나간다.** 따라서 인터넷에 노출되지 않은 TX360에는 **닿지 않는다.** 실제로 TX360 호스트는 **공개 DNS에서 조회조차 되지 않는다**(이 조사에서 NXDOMAIN 확인).
- 사내망에 바로 닿을 수 있는 Claude 채널은 **로컬 MCP를 띄울 수 있는 Claude Code와 Claude Desktop뿐**이다.
- 그런데 그 둘은 **일반 업무 사용자용 도구가 아니다.**

즉 **"일반 사용자 편의성"과 "사내망 도달"이 정면으로 충돌한다.** 이 충돌을 어떻게 푸느냐가 곧 채널 선택이다.

**푸는 방법은 세 갈래뿐이다**

| 갈래 | 해법 | 해당 후보 |
|---|---|---|
| ① 사내 플랫폼이 대신 넘는다 | 사내망 안에 있는 플랫폼이 MCP를 품고, 외부로는 모델만 호출 | FabriX 에이전트, Brity Copilot |
| ② 우리가 직접 넘는다 | 사내 서버에서 에이전트를 돌리고 화면도 우리가 만든다 | Agent SDK 사내 호스팅, TX360 내장, Knox 봇 |
| ③ 경계를 연다 | TX360 MCP를 DMZ에 노출하거나 터널을 뚫는다 | Claude 웹 챗·Cowork + 커넥터 |

**결정된 것**

- **DMZ 노출은 배제한다.** 리모트 커넥터는 **Anthropic 클라우드에서 발신**되므로 `[미러 확인]`, 공개 노출 없이는 사내망에 닿지 않는다
- ⚠️ **단 ①③이 탈락한 건 아니다.** **Enterprise MCP 터널**이 제3의 경로다 — 아웃바운드 전용이라 **인바운드 포트도 공개 주소도 IP 허용목록도 필요 없어 DMZ와 다르다** `[미러 확인]`. 신청·검토가 별도 결정 사항이다
- FabriX 회신과 조직 관리자 확인을 **기다리지 않고 진행한다**

**잠정 권고**

- **지금 바로 진행**: **④ Claude Code.** 이미 동작하고, 비개발 업무에도 쓰이고 있으며, **시트 안에서 추가 비용 없이** 돌아간다. 기다릴 이유가 없다
- **병행 — 배포 방식 전환**: 현재의 JSON 수동 편집을 **`.mcpb` 확장 패키지**로 바꾼다. 30명 배포의 핵심 과제다(7절)
- **최종 배포 후보**: **⑤ FabriX 에이전트.** 사내 플랫폼이라 사내망 문제가 구조적으로 해소된다. **TLS 관문 통과가 조건**
- **병행 문의**: **⑩ Brity Copilot.** 기술적으로는 가장 싸지만 관할이 달라 **조직적 공수가 크다.** 일정을 여기에 걸지 말 것

**남은 관문 넷**

1. **MCP 터널을 신청할 수 있는가** — 되면 ①③이 살아나고 편의성 최상 채널이 열린다. research preview이고 Cloudflare가 경로에 개입한다는 점은 심의 대상이다
2. **`.mcpb` 설치가 우리 환경에서 되는가** — 30분이면 판가름난다. 배포 계획 전체가 여기 걸려 있다(7절)
3. **TX360 서버의 TLS를 정상화할 수 있는가** — 지금은 클라이언트에서 보안수준을 낮춰 접속 중이다. **FabriX를 포함한 여러 후보의 공통 전제조건**이다(2절)
4. **어느 수준의 화면까지 필요한가** — 텍스트로 충분한지, 카드·필터가 필요한지에 따라 채널이 갈린다(5절)

**이미 해소된 전제** `[사내 확인]`
- Claude Enterprise 계약 중 (1인당 월 $150, 매달 초기화) → **Claude 채널은 추가 예산 없이 쓸 수 있다**
- 조직 테넌트 구성됨 (데스크톱 설정에 조직 ID 존재) → **조직 단위 배포 경로가 열려 있을 가능성이 크다**
- Copilot 기능이 사내 메신저에 도입돼 있음 → 단 **관할이 달라 협의 공수가 크다**

## 1. 용어 정리

논의 전에 용어부터 맞춘다. 각 항목은 **정의 / 비유 / 이건 아님** 세 줄이다.

### 연결에 관한 용어

**MCP (Model Context Protocol)**
- **정의**: AI가 외부 시스템의 기능과 데이터를 쓸 수 있게 해 주는 표준 규약.
- **비유**: 노트북과 주변기기를 잇는 USB 규격.
- **이건 아님**: AI 모델도 아니고 제품 이름도 아니다. 규격일 뿐이다.

**MCP 서버**
- **정의**: TX360의 기능을 MCP 규격으로 내놓는 프로그램. "검색해줘", "문서 가져와줘" 같은 도구 목록을 제공한다.
- **비유**: TX360에 꽂는 USB 어댑터.
- **이건 아님**: AI가 아니다. 스스로 판단하지 않고 요청받은 기능만 수행한다.

**커넥터 (Connector)**
- **정의**: Claude 제품에 "이 MCP 서버를 쓰겠다"고 등록해 둔 것.
- **비유**: 휴대폰에 블루투스 기기를 페어링해 두는 것.
- **이건 아님**: 커넥터가 기능을 만들어 내지는 않는다. 이미 있는 MCP 서버를 가리킬 뿐이다.

**로컬(stdio) MCP vs 리모트 MCP** ← 이 문서에서 가장 중요한 구분
- **로컬**: 사용자 PC 안에서 프로그램으로 실행된다. Claude가 그 PC에서 직접 띄운다. → **사내망 접근 가능**
- **리모트**: 인터넷 주소(`https://...`)로 접속한다. **Anthropic 클라우드가 접속한다.** → **사내망 접근 불가**
- **비유**: 로컬은 내 책상 위 프린터, 리모트는 인터넷 인쇄소에 맡기는 것.
- **이건 아님**: "내 노트북에서 Claude 앱을 쓰니까 내 회사 네트워크로 나가겠지" — **리모트 커넥터에는 틀린 생각이다.**

### 확장·배포에 관한 용어

**스킬 (Skill)**
- **정의**: "이럴 땐 이렇게 해라"를 적어 둔 설명서 묶음. Claude가 필요할 때 읽는다.
- **비유**: 신입에게 주는 업무 매뉴얼.
- **이건 아님**: **네트워크 권한을 주지 않는다.** 매뉴얼이 잠긴 문을 열어 주지는 않는다. `[검증됨]`

**플러그인 (Plugin)**
- **정의**: 스킬·커넥터·명령어 등을 한 묶음으로 포장한 배포 단위.
- **비유**: 앱스토어에서 받는 앱 하나.
- **이건 아님**: 새 능력을 만드는 게 아니라 있는 것들을 묶어 배포하기 쉽게 한 것이다.

**마켓플레이스 (Marketplace)**
- **정의**: 플러그인을 모아 두고 조직 구성원이 설치하게 하는 배포처.
- **비유**: 사내 앱스토어.
- **이건 아님**: 결제나 거래 기능이 아니다. 목록과 설치 경로일 뿐이다.

**서브에이전트 (Subagent)**
- **정의**: 큰 일을 나눠 맡기는 보조 AI. 본체가 지시하고 결과만 받는다.
- **비유**: 팀장이 팀원에게 조사 업무를 떼어 주는 것.
- **이건 아님**: 별도 계정이나 별도 라이선스가 아니다.

**훅 (Hook)**
- **정의**: "이 시점에 이 명령을 자동 실행"하는 자동화 규칙.
- **비유**: 정해진 시각에 자동으로 켜지는 조명 타이머.
- **이건 아님**: AI가 판단해서 하는 게 아니라, 조건이 맞으면 기계적으로 실행된다.

### 화면에 관한 용어

**MCP Apps (인터랙티브 커넥터)**
- **정의**: 대화창 안에 카드·표·버튼 같은 화면을 띄우는 확장 규격.
- **비유**: 채팅방 안에서 열리는 미니 웹페이지.
- **이건 아님**: 모든 Claude 제품이 지원하지는 않는다. 5절 참조.

**Artifact**
- **정의**: Claude가 만든 문서·표·웹페이지를 대화 옆 패널에 펼쳐 보여 주는 기능.
- **비유**: 회의 중 옆에 띄우는 화이트보드.
- **이건 아님**: 우리 시스템에 연결하는 수단이 아니다. 결과를 보여 주는 방식일 뿐이다.

**프로젝트 (Project)**
- **정의**: 관련 대화와 자료를 묶어 두는 claude.ai의 작업 공간.
- **비유**: 업무별 폴더.
- **이건 아님**: 에이전트를 조직에 배포하는 수단이 아니다.

### 제품·서비스에 관한 용어

**Claude Code**
- **정의**: 터미널·IDE에서 쓰는 에이전트형 Claude. 파일을 읽고 명령을 실행한다.
- **비유**: 옆자리에 앉아 직접 키보드를 잡는 개발자.
- **이건 아님**: 코딩 전용 도구이긴 하나, 이 논의에서는 **사내망 MCP를 바로 붙일 수 있는 검증 도구**로서 의미가 있다.

**Cowork**
- **정의**: Claude Code의 엔진을 비개발자 업무(조사·문서 작성·자료 정리)에 맞춰 내놓은 별도 서피스.
- **비유**: 같은 엔진에 세단 차체를 씌운 차.
- **이건 아님**: 채팅의 한 모드가 아니다. **별도 서피스**다. `[미검증]`

**Agent SDK**
- **정의**: Claude Code의 알맹이(질문 → 도구 호출 → 결과 해석 → 답변 반복 루프)를 Python·TypeScript 라이브러리로 떼어낸 것.
- **비유**: 완제품 자동차에서 **엔진만** 사 오는 것. 차체·핸들·좌석(= 화면·로그인·운영)은 우리가 만든다.
- **이건 아님**: 화면도 로그인도 들어 있지 않다. "SDK를 쓰면 앱이 생긴다"가 아니다. `[검증됨]`

**Managed Agents**
- **정의**: 에이전트 루프와 실행 환경까지 Anthropic이 대신 돌려 주는 서버측 에이전트 서비스.
- **비유**: 엔진도 차체도 빌리고, 어디로 갈지만 우리가 지시하는 렌터카.
- **이건 아님**: Agent SDK와 다르다. 이쪽은 **호스팅까지 남이 한다.** `[검증됨]`

**시트 (Seat)**
- **정의**: 임직원 1인에게 배정되는 Claude 이용 권한. 사용량 한도가 딸려 있다.
- **비유**: 1인 1좌석 정기권.
- **이건 아님**: 우리가 만든 앱의 사용자에게 이 좌석을 쓰게 할 수 **없다.** 약관상 금지돼 있다. `[검증됨]`

### 보안·운영에 관한 용어

**MCP 터널**
- **정의**: 사내망 안에서 바깥으로만 연결을 걸어 두고, 그 통로를 통해 Claude가 사내 MCP 서버에 닿게 하는 방식. 인바운드 포트를 열지 않는다.
- **비유**: 안에서 밖으로 전화를 걸어 놓고 통화를 계속 열어 두는 것. 밖에서 초인종을 누르는 게 아니다.
- **이건 아님**: **DMZ 노출과 다르다.** 공개 주소도, 방화벽 인바운드 규칙도, IP 허용목록도 필요 없다. DMZ를 배제해도 이 선택지는 남는다.


**DMZ 노출**
- **정의**: 사내망과 인터넷 사이의 중간 구역에 서버를 내놓아 외부에서 접근할 수 있게 하는 것.
- **비유**: 건물 로비에 접수대를 두는 것. 외부인이 들어올 수 있지만 사무실 안쪽과는 분리돼 있다.
- **이건 아님**: 사내망 전체를 여는 게 아니다. 다만 **공개 DNS 등록 + 방화벽 허용**이 필요하므로 보안 심의가 무겁다.

**전송 방식과 deprecated**
- **정의**: MCP가 서버와 통신하는 방식. 지금 쓰는 `/sse`(HTTP+SSE)는 구형이고, MCP 규격이 **제거 대상(deprecated)**으로 분류했다. 현행 권장은 Streamable HTTP다.
- **비유**: 단종이 예고된 규격. 지금 쓰는 데는 문제가 없지만 새로 나오는 기기가 안 받아 줄 수 있다.
- **이건 아님**: 당장 못 쓴다는 뜻이 아니다. 급하지 않으나 **언젠가 해야 할 숙제**다.

**버전 고정과 공급망 위험**
- **정의**: 현재 설정은 브리지 패키지를 **실행할 때마다 그 시점의 최신 버전으로 내려받는다**(`npx -y`). 버전을 적어 두면 그 버전만 쓴다(버전 고정).
- **비유**: 매일 아침 누가 만들었는지 모르는 최신판 열쇠 복사기를 새로 받아서 내 사무실 열쇠를 꽂는 것.
- **이건 아님**: 그 패키지가 지금 악성이라는 뜻이 아니다. **검증 없이 언제든 바뀔 수 있는 구조**라는 뜻이다.

**데스크톱 확장 (MCPB, `.mcpb`)**
- **정의**: MCP 서버와 설정을 한 파일로 묶은 설치 패키지. 더블클릭하면 설정 폼이 뜨고, API 키를 거기에 넣는다.
- **비유**: 앱 설치 파일 하나. 설치 마법사가 필요한 것만 물어본다.
- **이건 아님**: 커넥터와 다르다 — 커넥터는 인터넷 주소를 등록하는 것이고, 이건 **로컬에서 뜨는 서버**를 설치하는 것이다. 예전 이름은 `.dxt`였다.

**인용(Citations)과 Search result 블록**
- **정의**: 답변에 "이건 어느 문서에서 왔다"를 달아 주는 기능. 내부 식별자도 출처로 쓸 수 있다.
- **비유**: 각주가 달린 보고서.
- **이건 아님**: MCP가 주는 기능이 아니다. **API 레벨 기능**이라 자체 구축에서만 확실히 쓸 수 있다.

### 세 줄로 압축하면

1. **커넥터는 연결**, **스킬은 사용법**, **플러그인은 포장**, **마켓플레이스는 배포처**다. 네 개는 층이 다르다.
2. **Cowork는 채팅의 모드가 아니라 별도 서피스**다.
3. **Agent SDK는 우리가 호스팅, Managed Agents는 Anthropic이 호스팅**한다.

## 2. 결정은 3층으로 나눠서 한다

후보를 뒤섞어 놓고 비교하면 결론이 안 난다. 세 축은 **서로 독립**이므로 따로 정해야 한다.

| 층 | 질문 | 선택지 |
|---|---|---|

### 현재 연결 설정이 말해 주는 것

지금 쓰고 있는 TX360 MCP 설정을 뜯어보면 위의 논의가 훨씬 구체적으로 좁혀진다. 구성을 요약하면 (내부 주소·키는 생략):

- 사용자 PC에서 `npx`로 **`mcp-remote`** 라는 외부 브리지 패키지를 실행한다
- 그 브리지가 TX360의 **`/sse` 엔드포인트**에 HTTPS로 접속한다
- 인증은 **개인 API 키를 `Authorization: Bearer` 헤더**로 전달한다
- 환경변수로 **사내 프록시를 지정하고, TX360 도메인만 프록시를 우회**해 직접 연결한다
- `NODE_OPTIONS`로 **TLS 보안수준을 낮추고(`SECLEVEL=0`) 시스템 인증서 저장소를 쓰도록** 한다

여기서 여섯 가지 사실이 나온다.

**1. TX360은 정말로 사내망 전용이다 — 공개 DNS에도 없다** `[검증됨]`

이 세션에서 조회해 본 결과 TX360 호스트와 그 상위 도메인 모두 **공개 DNS에서 응답이 없다(NXDOMAIN).** 방화벽에 막히는 수준이 아니라 **Anthropic 클라우드는 이 호스트의 이름조차 찾을 수 없다.**

이게 왜 결정적이냐면, 커넥터의 동작 방식이 이렇기 때문이다 `[미러 확인]`:

> "요청을 보내기 전에 Claude가 서버의 호스트명을 확인하고 결과를 검증합니다. 확인된 주소 중 **하나라도 전역 라우팅이 불가능한 주소면, HTTP 요청이 Anthropic 네트워크를 떠나기 전에 연결을 거부**합니다."

거부 대상에는 사설 대역(`10.` `172.16.` `192.168.`), CGNAT, 루프백, 공개+사설 혼재, IPv6 전용이 포함된다. **즉 이름이 안 풀리거나 사설 IP로 풀리면 시도조차 되지 않는다.**

**2. TX360 MCP는 원래 "리모트 MCP 서버"다. 로컬 MCP가 아니다** `[검증됨]`

`mcp-remote`는 "로컬 전용 클라이언트가 리모트 서버에 접속할 수 있게 해 주는 프록시"로 소개된 패키지다. 즉 TX360은 **HTTP 엔드포인트를 가진 리모트 서버**이고, 사용자 PC에서 도는 것은 **중계기**다.

- **좋은 소식**: 네트워크 도달 문제만 풀리면 구조적으로는 어느 채널에든 붙일 수 있다. MCP 서버를 새로 만들 필요가 없다.
- **나쁜 소식**: 지금 동작하는 이유가 **"사내 관리 PC에서 도는 Node 프로세스라서"**다. 그 전제가 깨지는 채널에서는 현재 설정을 그대로 쓸 수 없다.

**3. 현재 설정의 대부분이 PC 환경에 의존한다** ← 이 절에서 가장 중요한 발견

프록시 지정, 프록시 우회 목록, TLS 완화, 시스템 인증서 사용 — 네 가지 모두 **사내 관리 PC이기 때문에 가능한 설정**이다. 그런데 **Anthropic 클라우드 커넥터에도, FabriX에도, Managed Agents에도 `NODE_OPTIONS`를 넣을 자리가 없다.**

→ 만약 TX360의 TLS 구성이 표준 클라이언트가 거부하는 형태라면, **인증이나 네트워크를 따지기 전에 TLS 핸드셰이크 단계에서 먼저 실패한다.**

→ **확인 필요 (기술지원 질의 1순위)**: `SECLEVEL=0`이 필요한 이유가 무엇인가? 구형 암호화 스위트인가, SHA-1 서명인가, 짧은 키인가, 구버전 TLS인가? 이걸 모르면 **FabriX 연계도 같은 지점에서 막힐 수 있다.**

**4. 인증이 이미 "개인 키"다 — 권한 모델 논의의 출발점이 바뀐다**

공통 서비스 계정이 아니라 **임직원 개인 API 키**를 쓰고 있다. 즉 **사용자별 권한 분리가 이미 부분적으로 구현돼 있다.** 이건 좋은 출발점이다. 다만 형태가 **정적 Bearer 토큰**이라 다음 문제가 따라온다:

- 키가 **명령줄 인자**로 넘어간다 → 그 PC의 프로세스 목록에서 보인다
- 설정 파일에 평문으로 들어간다 → 배포·회수·교체 절차가 필요하다
- OAuth가 아니므로 **Claude의 조직 단위 IdP 인증(enterprise-managed auth)을 쓸 수 없다** `[미검증]`
- claude.ai 커넥터로 옮기면 정적 헤더는 **조직 공용 자격증명**이 되어 **개인별 구분이 사라질 가능성이 있다** `[미검증]`

**5. `/sse`는 사용 중단 예정인 전송 방식이다** `[검증됨]`

MCP 스펙은 HTTP+SSE를 `2025-03-26` 리비전부터 deprecated로 두었고, 현행 리비전에서 제거 대상으로 분류했다. Claude Code 문서도 "SSE는 deprecated이므로 HTTP 서버를 쓰라"고 안내한다.

→ 지금 잘 동작하는 것과 별개로 **Streamable HTTP 전환은 예정된 과제**다. 채널을 바꾸는 시점에 함께 처리하는 것이 효율적이다.

**6. 공급망 관점 — 브리지 버전이 고정돼 있지 않다**

`npx -y mcp-remote`는 버전을 지정하지 않아 **실행 시점의 최신 버전을 내려받는다.** 그리고 `mcp-remote`는 Anthropic이나 삼성SDS가 아닌 **외부 MIT 라이선스 패키지**다. `[검증됨]`

→ 특정 릴리스가 오염되면 **임직원 PC에서 개인 API 키를 손에 쥔 채 실행**된다. 최소한 **버전 고정**과 **사내 레지스트리 미러링**을 검토해야 한다.

## 5. UI 표현 수준

"챗 환경에서 어디까지 보여줄 수 있나"에 대한 답이다. **네 단계가 있고 단계마다 상한선이 다르다.**

| 단계 | 무엇 | 표현력 | 어디서 되나 |
|---|---|---|---|
| 1 | 텍스트 | 제목·요약·링크·표 | 전부 |
| 2 | MCP 콘텐츠 타입 | + 이미지·파일 참조 | 전부 |
| 3 | **MCP Apps** | + 카드·필터·버튼 등 진짜 UI | 웹·Desktop만 |
| 4 | **Artifacts** | + 문서·차트·대시보드 한 페이지 | Claude 구독 필요, Enterprise는 기본 OFF |

### 1단계 — 텍스트

**MCP 스펙은 마크다운·표·링크 렌더링을 아예 규정하지 않는다.** 전적으로 호스트 재량이다 `[검증됨]`. 실무적으로는 렌더링되지만 **보장이 아니라는 점**은 알아 둘 필요가 있다.

1차 범위(제목·요약·원문 링크)에는 이걸로 충분하다.

### 2단계 — MCP가 돌려줄 수 있는 것

콘텐츠 타입은 **정확히 5종**이다: `text` / `image` / `audio` / `resource_link` / `resource` `[검증됨]`

알아야 할 제약:

- ⚠️ **이미지는 base64 임베딩만 된다. URL은 불가능하다** — 스키마에 URL 필드가 아예 없다. 즉 **이미지를 보여주려면 그 바이트가 클라우드를 거쳐 간다**
- `resource_link`로 `https://` URI를 넘길 수는 있지만, **클라이언트가 그걸 렌더링한다는 보장이 스펙에 없다**
- `structuredContent`와 `outputSchema`는 **렌더링용이 아니라 검증·파싱용**이다. 표로 그려 준다는 규정은 없다
- **스펙에 결과 크기 제한이 없다** → 호스트마다 다르다

**권고 조합**: 검색 결과는 `resource_link` 배열 + `structuredContent`(기계 판독) + 요약 `text`(사람·모델 판독)를 함께 채우는 게 스펙이 의도한 형태다.

### 3단계 — MCP Apps: 대화 안의 진짜 UI

`ui://` 리소스로 HTML 페이지를 넘기면 호스트가 **샌드박스 iframe**에 띄운다 `[검증됨]`.

**할 수 있는 것**
- 클릭 가능한 결과 목록, 필터, 하이라이트 같은 실제 UI
- **`ui/open-link`로 원문 열기** — 이 건에 가장 유용하다
- `ui/update-model-context` — 사용자가 고른 문서를 모델 컨텍스트에 주입. 검색 UX에 잘 맞는다
- `ui/message` — 후속 질문 트리거

**제약**
- **외부 오리진을 CSP에 전부 사전 선언해야 한다.** `resourceDomains`(이미지·폰트·스크립트·스타일을 한 필드로 묶음), `connectDomains`(fetch·XHR·WebSocket), `frameDomains`, `baseUriDomains`. 미선언 시 기본값은 `default-src 'none'`
- 권한은 **4종뿐**: 카메라 / 마이크 / 위치 / **클립보드 쓰기**(읽기는 없음)
- ⚠️ **`ui/download-file`은 draft 전용**이라 stable(`2026-01-26`)에 없다. 샌드박스가 `allow-downloads`를 주지 않으므로 **직접 다운로드는 차단**된다
- **턴 간 상태 유지가 프로토콜에 없다**(localStorage로 우회하는 패턴)
- **지원: Claude 웹·Desktop ✅ / Claude Code는 공식 매트릭스에 행 자체가 없다**

> ⚠️ **사내망 이미지에 관한 주의**: 스펙상으로는 `resourceDomains`에 TX360 오리진을 선언하면 **사용자 브라우저가 사내망에서 직접 가져오므로 클라우드를 거치지 않는다.** 하지만 **Claude가 실제로 그렇게 구현했는지는 확인하지 못했다** `[미검증]`. 이걸 설계 전제로 삼기 전에 실물로 확인해야 한다.

### 4단계 — Artifacts

단일 HTML/MD 페이지를 claude.ai의 비공개 URL로 발행한다. 렌더 크기 상한 16 MiB `[검증됨]`.

⚠️ **MCP Apps와 규칙이 정반대다. 섞으면 안 된다.**

- **외부 이미지를 전면 차단한다. data URI만 허용된다**
- `fetch`·XHR·WebSocket은 자기 오리진과 Google Fonts만 닿는다
- 스크립트는 지정된 4개 CDN에서만 가져올 수 있다
- **다운로드는 별도 capability가 필요**하고 계정별로 활성화된다. 일반 링크·`blob:`·`data:`는 뷰어가 차단한다
- **Enterprise는 기본 OFF** — Owner가 켜야 하고, 역할 단위로 범위를 좁힐 수 있다
- **ZDR·CMEK·HIPAA 조직은 전면 불가**

### 인용·각주

**Search result 콘텐츠 블록**이 이 건에 정확히 맞는 기능이다 `[검증됨]`.

- `source`에 **`kb://article-1234` 같은 내부 식별자**를 넣을 수 있다. URL이 아니어도 된다
- `title`, `content`와 함께 넘기면 Claude가 **웹 검색 결과처럼 출처를 달아 인용**한다
- 베타 헤더 불필요, **ZDR 적격**
- ⚠️ **텍스트 전용 — 이미지는 넣을 수 없다**
- ⚠️ **API 레벨 기능**이다. 자체 구축(⑥⑧⑨)에서 쓰는 것이고, **MCP로 붙이는 ②④에서 동일하게 되는지는 확인하지 못했다** `[미검증]`

> **숨은 장점**: 자체 구축을 택하면 인용·각주가 **네이티브로** 지원된다. "이 답변의 근거가 어느 문서인가"를 사용자에게 보여주는 게 검색 에이전트 신뢰도의 핵심이라면, 이건 자체 구축 쪽의 실질적 이점이다.

### ⚠️ ZDR 트레이드오프 — 초기에 정해야 한다

**ZDR(무보존)을 켜면 Artifacts·Files API·MCP 커넥터가 모두 빠진다** `[검증됨]`. ZDR이 커버하는 것은 **Claude Code 추론뿐**이다.

즉 **보안 요구와 화면 표현력이 정면으로 충돌한다.** 나중에 켜면 이미 만든 것이 동작을 멈추므로, 설계 전에 결정해야 한다.

### 이 건에서 스킬에 담을 것

채널이 무엇으로 결정되든 **재사용되는 자산**이다. FabriX로 가면 지시문·플로우로 형태만 바꿔 옮기면 된다.

- **질의 해석** — "작년 계약서 양식" 같은 말을 TX360이 알아듣는 검색어로 바꾸는 규칙
- **검색 전략** — 넓게 찾고 좁힐지, 바로 정확히 칠지. 0건일 때 어떻게 재시도할지
- **되묻는 기준** — 결과가 너무 많으면 나열하지 말고 어느 부서·기간인지 되묻게
- **출력 형식** — 제목 / 한 줄 요약 / 원문 링크 / **왜 이게 맞다고 판단했는지** 한 줄
- **못 찾았을 때** — 없는 걸 지어내지 않고 "검색 범위에 없다"고 말하게
- **권한 밖 안내** — 공통 최소권한 키로는 안 보이는 자료일 때의 안내 문구

> 마지막 두 개가 체감이 가장 크다. 검색 에이전트에서 가장 흔한 불만이 **"없는데 있는 것처럼 답한다"**이기 때문이다.

## 7. 배포·설치 방법

"MCP를 어떻게 물리게 할 것인가"는 사용성의 핵심이다. 현재는 **설정 > 개발자 > 구성 편집에서 JSON을 직접 손보는 방식**인데, 30명 배포에는 맞지 않는다.

### 사용자 단계 수 기준 비교

| 방법 | 사용자 단계 | IT 사전배포 | 개인 키 처리 | 판정 |
|---|---|---|---|---|
| **MDM으로 관리 설정 푸시** | **0** — 그냥 나타남 | ✅ 완전 | ✅ 스크립트로 주입 | 최선이나 **문서상 3P 배포 전용** |

| 커넥터 UI | 4 | ❌ | ❌ 조직 공용 | **불가** |
| 수동 편집 (현재) | ~8 | ❌ | ❌ | 최악 |

### 커넥터가 안 되는 이유 — 세 겹이다

*"커넥터 만들어 놓고 연결하면 쉽지 않나"*가 자연스러운 질문인데, 우리 구성에서는 세 가지가 동시에 막는다 `[검증됨]`.

1. **로컬 서버는 커넥터 UI에 넣을 수 없다.** 커넥터는 URL을 입력하는 리모트 전용이고, 로컬(stdio)은 **개발자 설정이 유일한 경로**다
2. **정적 헤더 인증은 조직 공용 자격증명**이다. 베타이고 조직 한정인데다, 개인 API 키 모델과 근본적으로 안 맞는다
3. 리모트이므로 **공개 노출 또는 터널이 먼저 필요**하다. DMZ는 배제했으니 남는 건 Enterprise MCP 터널인데, 이건 별도 인프라 구축 과제다

> **결론은 그대로다 — 커넥터는 부적합하다.** 다만 사유가 "DMZ 때문"이 아니라 **"인증 모델 때문"**이 더 정확하다. 터널이 열려도 커넥터 경로(①③)는 **개인 키 문제가 그대로 남는다.** 조직 공용 정적 헤더를 쓰면 개인별 구분이 사라지기 때문이다.

### `.mcpb` 데스크톱 확장이 답인 이유

MCP 서버와 설정을 **한 파일로 묶은 설치 패키지**다(구 `.dxt`에서 개명).

- **Node.js가 Claude Desktop에 동봉돼 있다** `[검증됨]` — 이게 크다. 지금처럼 `npx`를 쓰면 **사용자 PC에 깔린 아무 Node 버전**을 타고, PATH에 없으면 실패한다. 확장 패키지는 그 의존성을 통째로 없앤다
- **설정 폼이 자동 생성된다.** API 키를 `sensitive`로 선언하면 **입력이 가려지고 평문 JSON이 아닌 보안 저장소**에 들어간다. JSON 편집이 사라진다
- **환경변수를 IT가 박아 넣는다.** 프록시·인증서 설정이 패키지에 들어가고 사용자에겐 보이지 않는다. OS별로 다르게도 된다
- **브리지 패키지를 안에 번들**할 수 있다 → 버전이 고정되고 실행할 때 외부에서 받아오지 않는다. **2절에서 지적한 공급망 위험이 같이 해결된다**
- 설치는 더블클릭 / 드래그앤드롭 / 설정 메뉴 세 가지

### ⚠️ 시작 전 30분 테스트

`.mcpb` 설치는 **3P 배포(Bedrock·Vertex 등 외부 모델을 물린 경우)에서 2026년 7월부터 기본 차단**됐다 `[미검증]`. 일반 claude.ai 조직(1P)은 기본 허용이지만, 확실한 방법은 하나다.

> **아무 `.mcpb`나 하나 만들어 실제 직원 PC에 설치해 본다.** 이 테스트 하나에 나머지 계획이 걸려 있다.

## 9. 권한 모델 권고안

### 현황

지금은 **임직원 개인 API 키**로 TX360에 접속하고 있고, **키마다 볼 수 있는 범위가 다르다.** 즉 사용자별 권한 분리가 이미 부분적으로 작동하고 있다. 좋은 출발점이지만, 그대로 두면 **조직 단위 배포가 불가능하다.** 사람마다 키가 다르니 조직 커넥터 설정에 넣을 값이 없기 때문이다.

### 권고 — 공통 최소권한 키 + 단계별 승격

| 단계 | 다루는 범위 | 인증 방식 | 배포 방식 | 별도 절차 |
|---|---|---|---|---|
| **1단계 — 검색·열람** | **전 직원에게 공개된 자료만** | 공통 **최소권한** 키 1개 | 조직 일괄 배포 | 없음 |
| **2단계 — 확장 열람** | 부서·직무별 제한 자료 | 개인 키 또는 그룹 키 | 신청 후 개별 배포 | **신청·승인** |
| **3단계 — 등록·수정** | 쓰기 | **반드시 개인 신원** | 개별 | **승인 흐름 필수** |

핵심은 **기본값을 가장 좁은 권한으로 두고, 더 필요할 때만 절차를 태우는 것**이다.

### 이 설계로 얻는 것

- **조직 단위 배포가 가능해진다.** 키가 하나로 고정되므로 조직 커넥터·플러그인 설정에 넣을 수 있다. → **claude.ai 웹 챗·Cowork로 가는 길이 열린다** (DMZ 노출이라는 별도 관문은 남는다)
- **사고 시 피해 범위가 작다.** 기본값이 "전 직원 공개 자료"이므로, 키가 유출돼도 원래 공개된 것 이상은 새지 않는다
- **배포·회수가 단순하다.** 30명에게 각자 다른 키를 배포·관리할 필요가 없다
- PoC 속도가 빨라진다

### 이 설계로 잃는 것 — 반드시 인지할 것

- **⚠️ TX360 로그에서 개인 구분이 사라진다.** 모든 조회가 같은 계정으로 기록된다. Claude 쪽 **Compliance API**에 "누가 Claude에서 무엇을 물었는지"는 남으므로 `[검증됨]`, 사고 조사 시 **두 로그를 시각으로 대조**해야 재구성된다.
  → **사전에 확인할 것**: 두 로그의 타임스탬프 정밀도와 보존 기간이 대조에 충분한가?
- **키 유출 시 영향 범위가 전체**다. 발급·배포·회수·교체 절차를 문서화해 두어야 한다
- 현재처럼 키가 **명령줄 인자와 설정 파일에 평문으로** 들어가면 그 PC에서 꺼내기 쉽다. 공통 키는 유출 파급이 더 크므로 **보관 방식을 함께 개선**해야 한다

### ⚠️ 빠지기 쉬운 함정 — 사번 헤더로 권한을 판단하지 말 것

"공통 키를 쓰되 누가 물었는지는 사번을 헤더로 같이 보내자"는 발상이 자연스럽게 나온다. **감사 기록 용도로는 괜찮지만, 권한 판단에 쓰면 안 된다.**

이유는 간단하다. **헤더는 증명이 아니라 주장이다.** 그 서버에 네트워크로 닿을 수 있는 누구나 아무 사번이나 적어 보낼 수 있다. 그러면 접근 통제가 "네트워크에 닿을 수 있는가"로 무너진다. MCP 보안 문헌에서 **confused deputy**라 부르는 전형적인 실패다.

**원칙**: 권한은 **키가 가진 범위로만** 판단한다. 사번 헤더는 로그에만 쓴다. 진짜로 사용자별 권한이 필요해지면(2·3단계), 헤더가 아니라 **개인 인증**을 쓴다. 표준 방식은 **OAuth 2.0 Token Exchange(RFC 8693)**로, 원 사용자 신원이 보존되어 감사 로그가 사실과 일치한다. `[검증됨]`

### TX360 쪽에서 준비해야 할 것

- [ ] **"전 직원 공개 자료"의 정의** — 무엇이 1단계 범위인지 TX360에서 명확히 구분되는가
- [ ] 그 범위만 보이는 **최소권한 키 발급**이 가능한가
- [ ] 키 **발급·배포·회수·교체** 절차와 담당
- [ ] 2·3단계로 올라갈 때의 **신청·승인 흐름**
- [ ] 공통 키 사용 시 TX360 감사 로그에 남는 정보와 **보존 기간**

이 문서로 닫히지 않는 것들이다. **사람이 물어봐야 답이 나온다.**

### 11-1. FabriX 기술지원 회신으로 받을 항목 (접수 완료 상태)

1. FabriX 안에서 **외부 시스템 연계 MCP 서버를 호스팅**할 수 있는가? 아니면 이미 있는 MCP 서버를 **등록·연결**만 하는 방식인가?
2. **⚠️ TLS 관문** — TX360은 현재 클라이언트 쪽에서 TLS 보안수준을 낮춰야 접속된다. FabriX에서 이런 서버에 접속할 수 있는가? 사용자 지정 CA·암호화 스위트 설정이 가능한가? **불가능하다면 TX360 서버 쪽 TLS를 먼저 정상화해야 한다.**
3. **인증 전달** — 임직원 **개인 API 키**를 사용자별로 전달할 수 있는가, 아니면 에이전트 단위 공용 자격증명만 되는가? 후자라면 사용자별 권한 분리가 불가능해진다.
4. **사용자 신원** — 에이전트가 MCP 서버를 호출할 때 **호출한 임직원이 누구인지** 백엔드로 전달되는가?
5. **전송 방식** — `/sse`(HTTP+SSE)를 지원하는가? Streamable HTTP도 지원하는가?
6. **결과 표현** — 제목·요약·원문 링크 목록을 어떻게 렌더링하는가? 페이지 이동·정렬 같은 상호작용이 가능한가?
7. **모델** — 에이전트가 호출할 수 있는 LLM 목록은? **Claude가 포함되는가?**
8. **과금 주체** — 모델 호출 비용은 플랫폼 계약에 포함되는가, 부서 부과인가?
9. **감사·운영** — 누가 무엇을 질의했는지 로그가 남는가? 보관 기간은? 에이전트 버전 관리·롤백은?
10. **응답 크기 제한** — 도구 응답 본문 크기 상한이 있는가?
11. **화면 표현 수준** — 검색 결과를 카드·표로 그릴 수 있는가, 텍스트 목록인가? **이미지 표시**와 **파일 다운로드**는 지원되는가? (5절 기준을 그대로 적용해 비교하기 위함)

### 11-2. Knox 협업솔루션 담당자 질의

1. Knox Teams / Knox Messenger에 **봇 계정 또는 서비스 계정**을 발급받을 수 있는가? 신청 창구는 어디인가?
2. **아웃바운드 이벤트**가 있는가 — 봇이 멘션·DM을 받았을 때 우리 서버로 알려 주는 기능(웹훅·소켓)이 존재하는가? **이게 없으면 양방향 대화형 에이전트는 불가능하다.**
3. **발신 API**가 있는가 — 특정 채널·사용자에게 메시지를 보내는 API와 인증 방식은?
4. 양방향이 막힌다면 **단방향 알림 웹훅**만이라도 가능한가?
5. 봇 요청에 **사번·조직 정보가 전달**되는가? (권한 기반 검색에 필수)
6. 사내 앱 등록 시 **보안 심의 절차·소요 기간·필요 산출물**은?
7. 메신저 서버에서 우리 에이전트 서버로의 **네트워크 경로**를 열 수 있는가?
8. **⭐ Copilot 기능에 TX360을 지식소스로 등록할 수 있는가?** 사내 메신저에 이미 들어와 있는 것은 확인됐다 `[사내 확인]`. 남은 질문은 **등록 가능 여부와 협의 창구**다 — 관할 부서가 다르므로 **누구에게 요청해야 하는지부터** 확인이 필요하다.

### 11-3. 사내 Claude 조직 관리자 확인 항목

계약 자체는 확인됐다(Enterprise, 1인당 월 $150, 매달 초기화) `[사내 확인]`. 데스크톱 설정에 **조직 ID가 보이므로 조직 테넌트도 구성돼 있다** `[사내 확인]`. 남은 것은 **그 조직을 누가, 어디까지 설정할 수 있는가**다.

1. **조직 관리자(Owner) 권한이 누구에게 있는가?** 우리 부서에서 요청할 수 있는 창구는?
2. **조직 커넥터 등록**이 가능한가? 절차와 심의는? — 9절 권고안(공통 최소권한 키)을 실행하려면 이 경로가 필요하다
3. **조직 스킬·플러그인 배포**가 가능한가? 가능하다면 검색 지시문을 스킬로 표준화해 일괄 배포할 수 있다
4. **Cowork가 조직 설정에서 활성화**돼 있는가?
5. **ZDR(무보존)이 적용**돼 있는가? 적용 중이라면 **못 쓰게 되는 기능**(웹 Claude Code, Artifacts 등)을 확인했는가?
6. 좌석 한도의 **실제 차감 기준**과 **초과분 과금 정책**은? — 8절 비용 추정을 실사용량으로 검증하려면 필요하다
7. ⭐ **MCP 터널을 신청할 수 있는가?** research preview 상태이고 Enterprise 신청제라고 한다 `[미러 확인]`. 우리 조직이 대상인지, **지원 범위가 claude.ai 웹만인지 Cowork·모바일까지인지** 확인이 필요하다. 되면 ①③이 살아난다
8. ⭐ **Anthropic 담당자에게**: *"일반 Team/Enterprise 배포에서 Claude Desktop의 관리 설정으로 MCP 서버를 푸시할 수 있는가? MDM이나 관리자 콘솔 경로가 있는가?"* — **"예"면 배포가 사용자 단계 0이 된다**(7절). 이 질문 하나가 배포 난이도를 가른다

### 11-4. 정보보호·보안 심의 사전 확인

1. TX360 검색 결과 본문이 **외부 모델로 전송되는 것**에 대한 판단 기준은?
2. 개인정보·기밀 등급 자료가 검색 결과에 포함될 수 있는가? 포함된다면 **필터링 지점**은 어디인가?
3. TX360 MCP를 **DMZ에 노출**하는 방안이 심의를 통과할 여지가 있는가? (통과 불가라면 후보 ①③이 완전히 탈락한다)
4. 임직원 PC에서 **외부 npm 패키지를 실행**하는 현재 방식에 대한 정책은?

## 12. 권고와 다음 결정

### 12-1. 지금 말할 수 있는 것

**터널이 열리면 유력해지는 후보**

- **① Claude 웹 챗** — **편의성이 후보 중 최상**이다. DMZ는 배제했지만 **Enterprise MCP 터널**이 남아 있다. 터널 신청이 되면 단숨에 최종 배포 1순위권으로 올라온다.
  게다가 **9절 권고안(공통 최소권한 키)을 채택하면 조직 커넥터 배포까지 함께 열린다** — 관리자가 한 번 등록하면 30명이 아무것도 설치하지 않는다.
  ⚠️ 걸림돌은 셋: research preview라 **SLA가 없고**, 경로에 **Cloudflare가 제3자로 들어가며**, 터널 인프라(컨테이너 2종 + 인증서)를 우리가 운영해야 한다.
- **③ Cowork** — 같은 경로를 쓰지만 **터널이 Cowork까지 커버하는지, 로컬 MCP를 쓸 수 있는지 둘 다 미확인**이다. ①이 먼저 풀린 뒤에 보는 게 순서다.

**바로 쓸 수 있는 후보**

- **④ Claude Code** — 이미 동작하고, 비개발 업무에도 쓰이고 있으며, **시트 안에서 추가 비용 없이** 돌아간다. **지금 시작할 수 있는 유일한 후보**다.
  남은 과제는 **배포 방식**이다. 현재의 JSON 수동 편집을 `.mcpb` 확장으로 바꾸면 사용자 단계가 8에서 3으로 줄어든다(7절).
- **② Claude Desktop** — 같은 로컬 MCP 경로를 쓰면서 **MCP Apps까지 지원하는 유일한 생존 채널**이다. 카드·필터 같은 화면이 필요해지면 여기가 답이 된다(5절).

**확인 결과에 달린 후보**

1. **⑤ FabriX 에이전트** — 사내 플랫폼이라 사내망 문제가 구조적으로 해소되고 노코드로 만들 수 있다. **TLS 관문만 통과하면 최종 배포 1순위.**
2. **⑩ Brity Copilot** — **기술적으로는 가장 싸고, 조직적으로는 가장 비싸다.** 관할이 달라 협의 공수가 크고 일정을 우리가 통제할 수 없다. 병행 문의하되 여기에 일정을 걸지 않는 게 안전하다.

**필요할 때 꺼낼 카드**

- **⑥ Agent SDK 사내 호스팅 / ⑧ TX360 내장** — 위 후보들로 충족되지 않는 요구사항이 확인됐을 때. 통제력은 최고지만 만들 것이 가장 많고 **API 예산이 별도로 든다.**

**보류**

- **⑦ Managed Agents** — 베타이고 ZDR 대상이 아니다. ⑥ 대비 이점이 현 상황에서 크지 않다.
- **⑨ Knox 봇** — 공개 근거가 전혀 없다. Knox 쪽 전제조건(11-2 체크리스트) 확인 전까지는 평가 자체가 불가능하다.

### 12-2. 단기와 최종을 분리한 제안

| 구분 | 채널 | 목적 |
|---|---|---|
| **지금** | ④ Claude Code | 검색 품질·지시문·결과 형식을 확정하고 **실사용을 시작한다.** 시트 안이라 추가 비용이 없다 |
| **지금 (병행)** | ④ 배포 방식 전환 | `.mcpb` 설치 테스트 → 확장 패키지 제작. 30명 배포의 관문 |
| **화면이 더 필요해지면** | ② Desktop + MCP Apps | 카드·필터·원문 열기가 필요할 때. 지금 쓸 수 있는 채널 중 유일하게 지원 |
| **터널 신청이 되면** | ① 웹 챗 | 설치 없이 브라우저만으로. 9절 권고안과 합치면 조직 일괄 배포까지 |
| **회신 후** | ⑤ FabriX | 같은 시나리오를 같은 기준으로 재현해 비교한다. ⑩은 병행 문의 |
| **최종** | 확인 결과에 따라 결정 | 위 후보들로 안 되는 요구사항이 확인됐을 때만 ⑥·⑧을 검토한다 |

> **중요**: 지금 만드는 산출물(검색 지시문, 결과 형식, 잘 되는 질문·안 되는 질문 목록)은 **채널과 무관한 자산**이다. 스킬로 정리해 두면 FabriX로 가도 지시문·플로우로 형태만 바꿔 옮기면 된다(6절). 회신을 기다리는 동안 놀 필요가 없다.

### 12-3. 다음 회의에서 결정할 것

1. **`.mcpb` 설치 테스트를 언제 할 것인가** — 30분이면 되고, 배포 계획 전체가 여기 걸려 있다(7절)
2. **권한 모델 권고안(9절) 승인 여부** — 공통 최소권한 키 + 단계별 승격으로 갈 것인가. 승인되면 TX360 쪽에 최소권한 키 발급을 요청해야 한다
3. **TX360 서버 TLS 정상화 작업을 착수할 것인가** — 여러 후보의 공통 전제조건이다
4. **1차 성공 기준** — 무엇이 되면 "쓸 만하다"고 판단할 것인가 (정확도? 단계 수? 응답 시간?)
5. **④ Claude Code로 30명 실사용을 먼저 시작할 것인가** — 기다리는 동안 실제 사용 데이터를 모을 수 있다
6. **필요한 화면 수준** — 텍스트로 충분한가, 카드·필터가 필요한가(5절). 필요하면 ②로 옮겨야 한다
7. **ZDR 적용 여부** — 켜면 Artifacts·Files API·MCP 커넥터가 모두 빠진다. **나중에 켜면 만든 것이 멈추므로 지금 정해야 한다**(5절)
8. **MCP 터널을 신청·검토할 것인가** — **DMZ를 배제한 것과는 별개 결정**이다. 터널은 인바운드를 열지 않으므로 배제 사유에 해당하지 않는다. 되면 ①③이 살아난다

## 이 문서의 한계

정직하게 적어 둔다.

1. **대부분 공개 문서 기반 조사다.** 사내 확인으로 보완된 항목은 13절 `[사내 확인]` 표에 모아 두었다. 사내망 정책, 조직 관리자 설정 범위, TX360 운영 배포본은 여전히 확인하지 못했다.
2. **핵심 출처 일부가 차단됐다.** 좌석 가격, Cowork 제품 설명, Knox·FabriX·Brity 정보 전체가 검색 발췌 기반이다. 13절의 `[미검증]` 목록을 직접 확인해야 한다.
3. **실제 PoC 결과가 아니다.** 조사 환경이 사내망 밖이라 TX360 MCP로 시나리오를 돌려 보지 못했다. 비교 자료일 뿐이다.
4. **"Claude Code는 MCP Apps 미지원"은 매트릭스에 행이 없다는 사실**이지 공식 부정 진술이 아니다. Cowork도 마찬가지다.
5. **비용 계산은 30명 기준 가정이다.** 1인당 하루 5회·1회당 입력 8,000·출력 700 토큰을 가정했다. 또한 **시트 한도의 실제 차감 기준이 API 요율과 다를 수 있으므로**, 초기 몇 주 실사용량을 측정해 재확인해야 한다.
6. **Enterprise 좌석 체계에 문서 간 불일치**가 있다(단일 Enterprise 시트 vs 레거시 premium·Chat+Code 시트). 계약 조건 확인이 필요하다.
7. **MCP Apps가 Claude에서 실제로 어떻게 구현됐는지 확인하지 못했다.** 스펙상 가능한 것(사내망 오리진 선언 등)이 Claude에서도 되는지는 실물로 확인해야 한다.
8. **Desktop Chat 탭이 플러그인으로 전달된 MCP 서버를 받는지 문서에 없다.** 스킬과 훅은 지원이 확인됐다.
9. **`.mcpb` 설치가 우리 조직에서 허용되는지 확인하지 못했다.** 7절의 30분 테스트로 판가름난다.
10. **"UI가 이미지를 사용자에게 표시한다"는 규정을 어느 문서에서도 찾지 못했다.** 이미지 관련 문서는 전부 "모델이 본다"에 관한 것이다.
